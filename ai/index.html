Can AI defend a network?

There are plenty of evals of how well AI can hack. BlueBoot Security measures how well it defends: we run an AI agent as a SOC against simulated attacks and score how fast and well it detects and responds.

Get in touch Explore the demo

Red-team agents are the problem. Blue-team agents are a solution.

Agents are getting good at finding and exploiting vulnerabilities. In loss-of-control or terrorism scenarios, society needs AI that can defend against them.

  • Offensive evals are everywhere

    Model cards and Inspect Evals measure whether a model can solve capture-the-flag challenges and assist cyberattacks.

  • Defensive evals are missing

    Almost nothing measures whether an agent can spot an intrusion in real traffic, triage the alerts and contain it.

  • No score, no north star

    You can't improve what you don't measure. A defensive benchmark gives AI developers a target to build toward.

The same test we give SOCs

Many SOCs are already AI agents, and they do the job we want defensive AI to do. So we evaluate an agent exactly as we evaluate a SOC.

  1. 1

    Simulate an organization

    Users, workstations, servers and the network between them.

  2. 2

    Hide an attack in normal work

    Realistic employee activity alongside a scripted attack campaign (MITRE ATT&CK®).

  3. 3

    Give the agent a SOC's tools

    Log search, the alert queue and response actions such as isolating a host.

  4. 4

    The agent defends

    It triages, investigates and responds, on its own.

  5. 5

    Score against ground truth

    Every alert and action is matched to the known attack.

  • Time to detect

    From each attack step to the agent's first alert on it.

  • Time to respond

    From alert to containment.

  • Completeness

    Were all attack steps caught?

  • False alarms

    Alerts on normal work.

  • Containment

    Was the attack stopped before data left?

Built for Inspect

We'll package the evaluation as an Inspect task, so any model Inspect supports can be run against it, and submit it to Inspect Evals.

  • It measures defense, not hacking

    The attack is scripted. The agent under test only sees logs and defends, so its score never rewards offensive skill.

  • An eval and an RL environment

    The scorer can become a reward signal and the scenarios a training set, to improve defense directly.

  • datasetScenariosAn organization, a workday of activity and an attack, with its ground truth.
  • solverThe defending agentThe model under test, with log search, alerting and response tools.
  • scorerGround-truth matchDetection, response time, false alarms and containment, per attack step.

A starting point for blue-team evals

The goal is to open the door to measuring, and improving, AI's defensive capabilities.

  1. 1

    First scenario

    A bank's workday with a Carbanak-style attack. The demo scores simulated SOCs on it, one of them agentic.

  2. 2

    Inspect task

    Package it so anyone can run it against their own model.

  3. 3

    Publish

    Share the results and encourage others to build more blue-team evals.

  4. 4

    Iterate with users

    Feedback from the people running it decides what comes next.
