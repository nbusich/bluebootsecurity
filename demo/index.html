How the methodology works

Build a company with a known activity record

Automated employees do ordinary work while a separate simulation introduces attack activity. Each action retains its origin, time, machine and available execution outcome.

Collect what a defender can see

A SIEM collects and searches security logs and alerts. XDR connects signals across endpoints and other sources. This recorded example uses endpoint audit alerts collected by a security platform; it does not demonstrate a separate XDR integration.

Keep the answer key separate

For an evaluation, a SOC receives agreed security-platform access or a supported integration. Evaluator-only activity labels and scenario markers must be excluded from that feed. Access and available evidence are documented before comparison.

Label with evidence, preserve uncertainty

Time, machine, command and process relationships help associate logs with actions. A nearby timestamp alone is insufficient. Unconfirmed execution and ambiguous attribution remain explicit and are excluded from scored outcomes.

Evaluate responses, not just logs

A log proves visibility, not SOC understanding. Assess the SOC’s incident report and response against verified activity and a rubric defined in advance. Real response timing starts at an agreed evidence-availability point. No actual SOC is measured here.

This is a presentation replay, not a connected SOC or an evaluation access-control system. The excerpts are bundled locally.
